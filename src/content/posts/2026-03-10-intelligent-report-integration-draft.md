# 智能体创设平台对接确认清单

---

## 一、接口协议与鉴权

**1.1 API 协议是什么？**

- 追问：RESTful / gRPC / WebSocket？同步调用还是异步回调？
- 为什么问：决定你后端怎么封装调用层。如果是异步回调，你还要额外搭一个回调接收服务；如果是 WebSocket，前端体验会不同。

**1.2 鉴权方式是什么？**

- 追问：API Key / OAuth2 / JWT？Key 怎么申请、谁审批、过期策略是什么？到期前自动续还是手动续？
- 为什么问：Key 突然过期会导致所有报告生成中断，得提前知道续期流程。如果审批链路长，要预留时间。

**1.3 有没有请求频率限制？**

- 追问：QPS 上限是多少？日调用总量有没有限制？超限后是排队等待还是直接拒绝？对应的错误码是什么？
- 为什么问：60 家机构如果同时跑报告，并发量要算清楚。超限被拒绝的话需要有重试机制；排队的话前端要做等待提示。

**1.4 平台有没有沙箱/测试环境？**

- 追问：测试环境和生产环境的 Key 是分开的吗？环境切换走什么流程？有没有灰度机制？
- 为什么问：调 Prompt 阶段要跑几十上百次，不可能在生产上搞。Key 分开才能保证测试不影响线上。

## 二、数据交互方式

**2.1 数据是怎么流转的？**

- 追问：我们 Push 数据到平台，还是平台来我们的库 Pull？走什么网络通道——内网直连还是需要开防火墙策略？
- 为什么问：决定网络层面的准备工作。如果需要开策略，要提前走审批，不能卡在联调阶段。

**2.2 单次请求能传多少数据？**

- 追问：Token 上限是多少（32K / 128K / 更大）？请求体大小有没有限制？
- 为什么问：机构数据加报告模板的文本量不小。如果上下文窗口太小，你的一章内容可能塞不下必要指标，得拆分更细的调用。

**2.3 是否支持传入结构化数据？**

- 追问：是否支持在 Prompt 中传入 JSON / 表格数据？LLM 能正确理解和引用结构化字段吗？
- 为什么问：你的预处理层产出的就是结构化 JSON。如果 LLM 对结构化数据理解力差，就得把数据转成自然语言再传，增加一层转换成本和信息损耗。

**2.4 有没有知识库或 RAG 能力？**

- 追问：能不能把业务规则文档、报告模板、机构画像上传到平台的知识库，让 LLM 自动检索？如果可以，管理后台对我们开放到什么程度？
- 为什么问：有 RAG 的话，Prompt 不用塞满背景知识，可以大幅节省 Token、提高输出质量。需要确认我们能自己维护知识库内容。

**2.5 数据预处理的分工怎么定？**

- 追问：LLM 调用之前，数据预处理（计算同比环比、预警判断）是我们自己做完再传，还是可以在平台工作流里嵌入处理逻辑？平台能不能直接调我们的数据库或 API？
- 为什么问：决定你的后端和平台的职责边界。如果平台能调你的库，工作流可以少一层中转；如果不行，你得自己把数据查好、算好、打包好再传。

## 三、智能体能力边界

**3.1 底层用了哪些大模型？**

- 追问：目前支持哪些模型？能不能按任务指定不同模型（比如骨架生成用推理强的、章节填充用生成快的）？
- 为什么问：模型能力直接决定报告质量上限。不同任务对模型的要求不同——骨架需要逻辑推理，章节填充需要文本流畅度。能按任务选模型的话设计方案更灵活。

**3.2 能不能锁定模型版本？**

- 追问：能不能指定模型版本号（如 `gpt-4-2024-04-09`）？如果不能，模型升级时我们的 Prompt 怎么办？
- 为什么问：这是最容易踩的坑。你花两周调好的 Prompt，模型一升级可能输出风格全变、某些约束失效。能锁版本 = 你的 Prompt 投资有保障。

**3.3 实际可用的上下文窗口多大？**

- 追问：注意问「实际可用」——有些平台标 128K 但系统 Prompt 就吃掉一截。真正能给我们塞数据的有多少？
- 为什么问：直接决定一次 LLM 调用能处理多少数据，从而影响工作流要不要拆得更细。

**3.4 智能体能调用外部工具吗？**

- 追问：是否支持 Function Calling / Tool Use？能不能调用计算器、数据库查询、图表生成？
- 为什么问：如果支持 Function Calling，工作流设计思路会完全不同——比如 LLM 自己调你的数据库查数据，而不是你把所有数据全塞进去。但这个能力不是所有平台都有。

**3.5 输出支持哪些格式？**

- 追问：纯文本 / Markdown / JSON / HTML？是否支持 JSON Mode 或 Structured Output 模式？
- 为什么问：**JSON Mode / Structured Output 是幻觉控制的关键基础设施。** 有了它，LLM 会在模型层面被约束输出合法 JSON，比靠 Prompt 约束可靠得多。如果不支持，你的硬校验层工作量会大不少。

**3.6 是否支持流式输出（SSE）？**

- 追问：前端能不能边生成边展示？
- 为什么问：一份完整报告生成可能要几十秒甚至一两分钟。如果只能等全部生成完再返回，前端是一个空白等待；有 SSE 的话可以像 ChatGPT 那样逐段显示，用户体验差很多。

**3.7 并发能力怎么样？**

- 追问：最多支持多少个智能体实例同时运行？并发限制是平台级还是按项目配额？
- 为什么问：60 家机构如果同时跑，你可能需要几十个并行调用。如果平台只能串行或并发很低，出报告的总时间会很长。

## 四、工作流执行模型

**4.1 工作流是 DAG 还是纯顺序？**

- 追问：如果是 DAG（有向无环图，支持并行分支），最多多少并行分支？并行之间能不能共享上下文/变量？
- 为什么问：你的四章填充如果只能串行就是 4× 时间，能并行就是 1×。这个直接影响报告生成速度。

**4.2 支持条件分支和循环吗？**

- 追问：if/else 条件判断支不支持？能不能在循环里遍历 4 个章节各自调一次 LLM？
- 为什么问：循环可以减少重复配置——你不需要手动写 4 个几乎一样的章节生成节点。条件分支可以做差异化处理（比如某个指标正常就跳过详细分析）。

**4.3 超时怎么处理？**

- 追问：单步骤超时是多少？整个工作流超时呢？超时后是失败重试还是跳过继续？
- 为什么问：LLM 调用偶尔会慢。如果你的工作流某一步超时直接终止，前面步骤的产出就全丢了；如果支持重试或者跳过继续，至少能拿到部分结果。

**4.4 能不能嵌入自定义代码？**

- 追问：工作流里能不能嵌入我们自己的逻辑（Python/Java 代码）？比如数据清洗、图表数据提取、硬校验规则。
- 为什么问：你的数据预处理、图表数据计算、硬校验这些纯计算逻辑，放自己后端最可靠；但如果平台支持嵌入，可以减少跨系统调用次数，架构更简洁。

**4.5 错误处理与重试策略？**

- 追问：某一步失败后，工作流是整体终止还是能配置重试？最多重试几次？能不能配置降级策略（比如 LLM 调用失败就输出模版报告）？
- 为什么问：决定了你的鲁棒性。银行系统里不能因为 LLM 偶尔抽风就让整份报告出不来。

## 五、数据安全与合规

**5.1 数据传输是否加密？**

- 追问：整个链路是否 TLS 1.2+？内网通道是否需要额外配置？
- 为什么问：机构经营数据属于敏感数据，传输加密是底线。

**5.2 平台会不会存储我们传入的数据？**

- 追问：存在哪里、存多久、哪些人有权限看？有没有操作审计日志？
- 为什么问：虽然是自己银行的平台，但不代表数据可以随便放。要搞清楚数据在那边有没有做访问控制和审计。

**5.3 模型会不会用我们的数据做训练？**

- 追问：不管底层是什么模型，我们传入的数据会不会被用于训练、微调或任何形式的模型改进？这个开关确认关了没有？
- 为什么问：**这是最核心的底线之一。** 银行对数据用途极其敏感。内部平台也不一定默认关闭训练数据采集，必须明确确认。

**5.4 数据脱敏标准对齐**

- 追问：银行内部对机构数据脱敏有没有统一规范？我们按哪个标准来？
- 为什么问：确认双方用同一套标准，不要这边脱了那边没脱、或者过度脱敏导致数据不可用。

**5.5 数据删除**

- 追问：如果需要清除历史数据，能不能操作？怎么确认删干净了？
- 为什么问：即使是内部共享，也应该有数据生命周期的管理约定。

**5.6 合规状态**

- 追问：平台有没有通过银行内部的安全合规审核？我们还需要再走一遍评审吗？
- 为什么问：如果平台已经过审，你可以复用安全评估结果；如果没过，你得预留评审时间。

## 六、资源配额与成本

**6.1 我们能用多少资源？**

- 追问：并发调用数、日调用总量、存储空间的配额是多少？是按需使用还是提前申请？
- 为什么问：你得按配额来算架构——如果并发限制很低，就只能串行跑报告，工作流设计要相应调整。

**6.2 高峰期会不会被挤占？**

- 追问：多项目共用平台的话，资源是怎么分配的？有没有项目级隔离或优先级保障？
- 为什么问：内部平台往往是多个团队共用，别的项目跑大了你的资源可能被挤占，导致报告生成变慢。

**6.3 内部怎么结算？**

- 追问：按调用次数、Token 消耗、还是按报告份数？有没有免费额度给我们调 Prompt 阶段用？
- 为什么问：Prompt 调试阶段调用量很大，如果按 Token 计费，调优成本需要提前和领导报备。

**6.4 超额了怎么处理？**

- 追问：自动限流停服，还是走审批扩容？扩容审批要多久？
- 为什么问：出了问题被限流，报告出不来，压力直接到你这。

---

## 七、稳定性与变更管理

**7.1 平台可用性怎么样？**

- 追问：有没有内部的服务等级承诺？计划内维护一般什么时候做、提前多久通知？
- 为什么问：如果你的报告生成任务被安排在维护窗口内，可能自动失败。需要知道维护规律，排任务的时候绕开。

**7.2 模型变更怎么管？**

- 追问：底层模型升级或切换时，谁来通知谁、提前多久？模型变更后已有的 Prompt 和工作流需不需要重新适配？谁负责验证兼容性？
- 为什么问：这是 Prompt 投资的最大风险。内部平台的模型变更可能没有外部商业 API 那么规范的版本管理。你得搞清楚变更流程和通知机制，避免「某天突然发现报告质量跳水，排查半天才发现模型换了」。

**7.3 平台升级有没有灰度机制？**

- 追问：升级前我们能不能在沙箱环境先验证？有没有灰度窗口让我们跑回归测试？
- 为什么问：给你留一个验证窗口，总比直接推全量然后你紧急修 Prompt 强。

**7.4 出问题找谁？**

- 追问：有没有固定的对接人/团队？日常沟通是拉群还是走工单？响应时效大概怎么样？
- 为什么问：内部协作最忌讳「出了问题不知道找谁」。提前定好责任人，省去来回打听的时间。

## 八、问题排查与协作

**8.1 能不能看调用日志？**

- 追问：每次 LLM 调用的完整 Prompt 输入和输出能不能查到？日志保留多久？对我们可以开放到什么程度——自助查还是需要你们配合调？
- 为什么问：你看历史记录里我们的项目背景——你习惯用截图分享终端输出和错误信息来调试。对接智能体平台之后，你的调试对象从本地代码变成远程 LLM 调用，**日志就是你的调试界面**。能不能自助查决定了你排查问题的效率。

**8.2 有没有错误码文档？**

- 追问：超时、鉴权失败、内容审核拦截、模型过载，各自对应什么错误码？
- 为什么问：没有错误码文档的话，每次出问题都得等对方回复「这个错误是什么意思」，浪费大量时间。

**8.3 Prompt 能不能在线调试？**

- 追问：平台有没有 Prompt 在线编辑和调试工具？能不能实时看到 Token 消耗和响应耗时？
- 为什么问：如果有在线调试工具，你可以直接在平台上迭代 Prompt，不需要每次改完代码部署一遍。

**8.4 异常告警有没有？**

- 追问：调用失败率或延迟超过阈值时能不能自动通知我们？通过什么渠道（企业微信/邮件）？
- 为什么问：你不可能 24 小时盯着监控。有告警才能第一时间知道出事了。

**8.5 联调怎么安排？**

- 追问：我们对接联调，你们侧谁来配合？走什么流程？联调窗口能有多长？
- 为什么问：预约定好联调窗口和对接人，避免「想调的时候对方在忙别的」。

---

## 九、长期规划

**9.1 平台后面有什么规划？**

- 追问：近期会不会上新模型、新工具、新的工作流特性？未来的能力路线图是什么样的？
- 为什么问：你现在设计的 Prompt 和工作流架构，受平台能力约束。了解路线图可以避免「刚做完就发现平台要支持某个能大幅简化架构的功能」。

**9.2 我们能不能提需求？**

- 追问：如果我们在使用中发现需要的能力，走什么渠道反馈？有没有受理和排期机制？
- 为什么问：内部平台最大的好处就是能推动迭代。把反馈渠道走通，你的使用体验会越来越好。

**9.3 我们的资产归谁管？**

- 追问：我们在平台上创建的 Prompt 模板、工作流配置、知识库内容、历史报告，这些的管理权是怎么定的？如果需要迁移到别的平台，能不能完整导出？
- 为什么问：虽然是内部，但「资产归属」还是要明确，避免将来部门调整时出现扯皮。
